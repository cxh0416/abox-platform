# ABox 双路 CAN Port

内部资料，不作为业务对接协议对外交付。

`hardware/api/include/abox_can_port.h` 定义经典 CAN 的帧、初始化、发送入队、FIFO0 读取和停止接口；分别由 `hardware/mcu/stm32f105` 和 `hardware/mcu/gd32f105` 实现。应用通过 `abox_platform_attach_f105_app(... CAN)` 或显式调用 `abox_platform_attach_can_port(target HARDWARE ...)` 接入，送餐车可用 `-DABOX_USE_CAN_PORT=ON`。默认送餐车构建不启用该 Port，也不恢复旧 CAN 业务。

| ABox 通道 | STM32 | GD32 | 既有引脚合同 |
| --- | --- | --- | --- |
| 0 | CAN1 | CAN0 | PA11 RX、PA12 TX |
| 1 | CAN2 | CAN1 | PB12 RX、PB13 TX |

初始化使用当前 APB1 时钟、18 时间份额、采样点 16/18 和 1 时间份额的 SJW。只有能够用整数分频精确得到的波特率才会成功；APB1 为 36 MHz 时，125、250、500 和 1000 kbit/s 均可表示。两个控制器使用共享过滤器分界 14，分别使用过滤器 0 和 14，以 32 位掩码全接收模式送往各自 FIFO0。需要硬件过滤或不同采样点的产品不能假定本配置满足其总线合同。

Port 独占所选控制器及 FIFO0；调用方负责串行化调用和及时轮询，不能同时由厂商中断回调消费同一个 FIFO。接入公共 Port 后，标准 STM32 板级启动自动跳过 `MX_CAN1_Init`/`MX_CAN2_Init`；HAL MSP、时钟和引脚仍由板级代码提供，之后由应用调用 `ABoxCanPort_Init`。没有接入 Port 的 STM32 产品保持原有 CAN 启动行为。已由其他代码初始化的 HAL 句柄仍会被拒绝。GD V1 正常模式配置上述默认引脚，并依据既有板级合同将对应 `CANx_STB` 拉低；静默回环不配置 CAN 引脚或待机脚。停止时须先停止通道 1，再停止通道 0，因为两路共享过滤器及 CAN0 时钟。

发送返回 1 表示帧已进入硬件邮箱，0 表示邮箱忙，-1 表示未初始化或参数错误；不代表帧已上总线、获得 ACK 或由对端执行。`ABoxCanPort_SendTracked` 同时返回本次占用的邮箱号，调用方需自行处理并发和复用前的历史完成事件；它本身不提供完成回执。读取返回 1 表示获取到一帧、0 表示 FIFO 空、-1 表示参数或帧错误。支持 11/29 位标识、数据/远程帧及 DLC 0..8；远程帧数据不使用。`ABoxCanPort_Init` 保持自动重发开启、自动 bus-off 恢复关闭和各 MCU 原有 FIFO 行为；`ABoxCanPort_InitWithOptions` 可显式选择自动重发、bus-off 恢复及接收 FIFO 覆盖策略。

`ABoxCanEvents` 是可选的发送完成和中断服务：分别报告成功、仲裁丢失、发送错误和取消；在复用邮箱前先处理其旧完成事件。取消请求只写请求位，不回写其他邮箱的完成标志。回调在调用方上下文执行，同一控制器的任务与中断必须使用同一把锁；接入事件服务后不能再混用普通 Send。GD FreeRTOS 启动向量和中断优先级由平台配置，标准 STM32 板级中断入口也会分发事件；自定义 STM32 中断入口需自行调用分发接口，并设置与调度器相容的优先级。GD 的既有 HAL 回调桥接用于迁移现有产品，仍复用公共事件服务，不能与另一中断消费者同时接管控制器。当前不提供自定义过滤规则及 FIFO 溢出通知。

GD V1 台架使用 RAM 目标和两路控制器静默回环，在 36 MHz APB1 下分别验证 250/500 kbit/s、标准帧、扩展帧、远程帧、两路共享过滤器与停止顺序；没有向外部 CAN 线发送帧。STM32 实现通过固定 HAL 头文件交叉编译及主机桩测试，V2 实板回归、GD 收发器/线束/真实对端和负载测试尚未完成。

公共 Port 不能与已有中断消费者同时接管相同控制器。公共主机测试覆盖两种芯片的邮箱结果、复用、取消、bus-off 事件、GD 回调桥接及 V1 上电待机；清扫车 V1 实际外部总线、收发器、整车及 OTA 仍需实测。
