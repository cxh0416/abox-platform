# ABox 经典 CAN 接口

内部资料，不作为业务对接协议对外交付。

`abox_can_port.h` 定义经典 CAN 配置、轮询收发与停用，`abox_can_events.h` 定义可选的邮箱完成、接收和错误事件。STM32F105 和 GD32F105 分别实现相同接口；板级启动不隐式初始化 CAN。

| 逻辑通道 | STM32 | GD32 | 现有 ABox 引脚 |
| --- | --- | --- | --- |
| 0 | CAN1 | CAN0 | PA11 RX、PA12 TX |
| 1 | CAN2 | CAN1 | PB12 RX、PB13 TX |

`ABoxCanConfig` 要求调用方显式设置波特率、段 1、段 2、同步跳转宽度、模式、自动重发、Bus-Off 自动恢复和接收 FIFO 覆盖策略。段与跳转宽度以时间份额表示：段 1 为 1..16，段 2 为 1..8，跳转宽度为 1..4 且不超过段 2。分频必须使当前 APB1 时钟精确得到所请求的波特率；非法参数或无法表示的时序返回失败。支持正常、回环、静默和静默回环模式。

两路使用共享过滤器分界 14，各有 14 个 32 位掩码过滤器。初始化时槽 0 使用传入的规则并连接 FIFO0，其余槽停用；可通过 `ABoxCanPort_SetFilter` 配置其他槽并选择 FIFO0 或 FIFO1，空规则表示停用该槽。规则中的过滤开关关闭时接收全部帧；启用时可按标准或扩展标识及掩码匹配，并可选择区分数据帧和远程帧。两路共享过滤器硬件，初始化和规则修改须跨两路串行化，配置期间可能丢帧。`ABoxCanPort_ReceiveFifo` 可轮询两个 FIFO；事件服务可选提供 FIFO1 接收和 FIFO0/FIFO1 溢出回调。溢出标志可能合并多次丢帧，不能作为丢帧计数。使用事件服务时，同一控制器的中断和任务必须由同一把锁串行化，同一 FIFO 不能同时交给轮询和事件消费者。自定义 STM32 中断入口须配置相关 RX0/RX1 IRQ 并设置与调度器相容的优先级，调用 `ABoxCanPort_DispatchEventIrq`；平台 GD FreeRTOS 向量执行相应分发。

`Send` 返回 1 仅表示帧进入邮箱，0 表示邮箱忙，-1 表示错误；不表示已获总线 ACK 或对端执行。事件服务区分成功、仲裁丢失、发送错误及取消，在复用邮箱前先消费旧结果；取消只写中止请求位，不回写其他邮箱的完成标志。事件回调在调用方上下文执行，诊断快照保留 F105 控制器的标准化寄存器字段。

通道 1 必须先于通道 0 停止，因为两路共享资源。`ABoxCanPort_Stop` 可等待厂商驱动完成，适合任务上下文；`ABoxCanPort_Suspend` 不依赖调度时钟，用于已串行化的快速断电路径，会丢弃待发帧，之后须重新 Init。STM32 挂起保持控制器复位并保留 MSP 所有权，GD 实现使用非阻塞复位。引脚与收发器通过可选 `ABoxCanPort_BindBoard` 回调由板卡配置；标准 ABox V1 在板初始化时绑定既有的 GD 引脚和待机控制，STM32 标准板仍由 HAL MSP 配置引脚。自定义板须提供自己的配置，回调在挂起路径中不能阻塞。任何情况下都不能以接口成功代替外部电平、总线或运动反馈。

历史 GD V1 静默回环、其他已记录的现场结果只对应当时构建。对本轮接口和产品迁移，主机测试与交叉构建不证明新固件在实板上收发、断电恢复或驱动车辆；相关现场验证应独立执行。
